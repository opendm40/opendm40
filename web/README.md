# DM40 Web

Локальное веб-приложение для Alientek DM40A/B/C. Экран повторяет компоновку
[DM40-Wireless](https://github.com/Urobotos/DM40-Wireless): оранжевые показания,
вспомогательные дисплеи, AUTO/RUN/HOLD, REL, шесть ячеек памяти, график и кнопки режимов.
Без сборки, CDN, сервера Bluetooth и зависимостей для запуска.

## Запуск

**Один файл:** откройте [dm40.html](dm40.html) двойным щелчком в Chrome/Edge.
Стили и скрипты уже встроены; сервер и интернет для интерфейса не нужны.
Деморежим работает без прибора. Доступ к Bluetooth/Serial для локального файла
зависит от браузера и его настроек; приложение проверяет наличие API.
Если браузер не разрешает подключение из файла, используйте localhost, как ниже.

Пересобрать автономный файл после изменения исходников:

```sh
python3 web/build_standalone.py
```

**Модульная версия через сервер:**

Из корня репозитория:

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory web
```

Открыть **http://localhost:8080** в Chrome/Edge. Не открывать `index.html` через
`file://`: этот исходный файл использует ES-модули (для двойного щелчка предназначен
`dm40.html`). На другом компьютере потребуется HTTPS,
обычный HTTP по LAN-адресу не предоставляет защищённый контекст для аппаратных API.
Сервер раздаёт только каталог `web`, не прошивки и прочие файлы репозитория.

Нажать **Деморежим**, чтобы проверить интерфейс без прибора. Демо помечается на экране
и в CSV; подключение к реальному прибору требует завершения демо.

## Подключение

1. Включить Bluetooth на DM40 и открыть на нём экран мультиметра.
2. Закрыть другие клиенты DM40.
3. Выбрать **Bluetooth LE**, нажать **Подключить** и выбрать прибор в окне браузера.
4. Разрешить браузеру доступ. Приложение проверяет идентификатор DM40 командой discovery.

BLE-профили проверяются по доступным характеристикам и их свойствам:

| Service | Write | Notify | Источник |
| --- | --- | --- | --- |
| FFF0 | FFF3 | FFF1 | Urobotos/DM40-Wireless |
| FFF0 | FFF1 | FFF2 | rockets-cn/dm40ble, mriscoc/DM40Visor |
| FFFF | FF01 | FF02 | Анализ ATK-XTOOL, дополнительный профиль |

Все короткие UUID расширяются до `0000xxxx-0000-1000-8000-00805f9b34fb`.
Выбор допускает переименованные устройства; после выбора проверяется модель.

Web Bluetooth работает с **BLE GATT**, а описанный в [docs/bt-protocol.md](../docs/bt-protocol.md) RFCOMM — это
**Bluetooth Classic**. Для Classic сначала выполнить сопряжение именно Classic-интерфейса
прибора в настройках Bluetooth ОС, затем выбрать **Web Serial / RFCOMM** и устройство
в системном диалоге. У проверенного DM40A BLE-интерфейс называется `DM40A`, а Classic —
`C-1-ATK-DM40-CALI`. До сопряжения Classic-интерфейс не отображался в Web Serial.
Chrome 117+ перечисляет сопряжённые устройства со стандартной службой SPP и открывает
RFCOMM напрямую — создавать `/dev/rfcomm*` не требуется. См.
[Serial over Bluetooth](https://developer.chrome.com/blog/serial-over-bluetooth).
Приложение не выполняет системное сопряжение самостоятельно.
Скорость порта настраивается; 115200 — значение по умолчанию для эмулируемого
порта, не подтверждённая скорость физического UART DM40.

Поддержка зависит от ОС, адаптера и сборки браузера. В Chrome на Linux для BLE может
потребоваться `chrome://flags/#enable-experimental-web-platform-features` и BlueZ.
Firefox/Safari не предоставляют эти API. См. официальные руководства
[Web Bluetooth](https://developer.chrome.com/docs/capabilities/bluetooth) и
[Web Serial](https://developer.chrome.com/docs/capabilities/serial).

## Управление

- Повторное нажатие V/A переключает DC → AC → AC+DC; Ω — обычное/ONLINE;
  диод — диод/прозвонка; Hz — частота/температура.
- AUTO открывает диапазоны для текущего режима с учётом модели A/B/C.
- RUN/HOLD и REL отправляют команды прибору. REL недоступен при HOLD.
- Нажатие на число сохраняет показание в одну из шести ячеек (кольцевая память).
- График показывает последние 180 отсчётов. MIN/MAX считаются по текущей серии.
- CSV содержит до 10 000 последних отсчётов текущей серии: время, режим, значение
  в базовых единицах, показание с единицей, REL, источник DEMO/DM40, исходный пакет.
- Смена режима/диапазона/REL или новое подключение начинает новую серию графика и CSV.
  HOLD не записывает повторные точки. «Очистить» очищает график и ячейки памяти.
- Данные находятся в памяти вкладки; перезагрузка их удаляет. Журнал ограничен
  последними 150 пакетами. Модель, период опроса и Serial baud rate задаются через ⚙.

## Протокол и ограничения

Framing, CRC и команды взяты из [docs/bt-protocol.md](../docs/bt-protocol.md).
Приоритет у исправленного запроса `AF 05 03 09 00 40`, а не исторического
`AF 05 03 09 01 3F`. CRC: `(-sum(bytes)) & 255`.

Единицы, режимы и диапазоны сверены с DM40-Wireless, commit
`b6dd1edef882bc283086a638b03d7e9872306b30`. Формат возвращает десятичные знаки,
знак и ступень приставки. Базовые масштабы: mV, µA, Ω, nF, Hz; в CSV преобразуются
в V, A, Ω, F, Hz. Учтён альтернативный формат напряжения `0x08` из DM40-Wireless.
Дополнительные AC/DC и Hz/% располагаются по таблице слотов этого клиента.
Для температуры используется фиксированная десятая доля градуса.

`FFFF` отображается как OL и не попадает на график. Неизвестный режим отображается
как MODE с hex-кодом, без численного показания. Бит 7 формата сохраняется в объекте
декодера и сыром пакете; интерпретация специальных значений прошивки нуждается в
проверке на реальном приборе. Для `0x84` в прозвонке используется масштаб 0.01 Ω,
как в исходном клиенте. Статус батареи отображается как исходные деления, без
выдуманного процента заряда.

Парсер собирает фрагменты потока, разделяет склеенные пакеты, проверяет ID, длину и
CRC. Запросы сериализованы и сопоставляются с ответом по команде. Тайм-аут завершает
соединение, чтобы запоздавший ответ не подтверждал следующую команду. Состояние
кнопок реального прибора обновляется из измерений, а не оптимистически.

**Проверено на физическом DM40A (13 октября 2026):** автономный `dm40.html`,
Chrome 144 на Linux с `--enable-experimental-web-platform-features`, подключение
через BLE, определение модели, получение обновляемых измерений напряжения
(0,27–0,31 мВ) и переключение RUN → HOLD → RUN с подтверждением в ответных пакетах.
Без этого флага в проверенном Chrome отсутствует `navigator.bluetooth`;
автономный файл при этом имеет защищённый контекст. В обычном Chrome флаг можно
включить через `chrome://flags/#enable-experimental-web-platform-features` →
Enabled → Relaunch. Приложение теперь сообщает об этом сразу при открытии файла.

**Web Serial также проверен на физическом DM40A:** Chrome 144 на Linux без
экспериментальных флагов, локальный `dm40.html`, системный диалог выбора
`C-1-ATK-DM40-CALI` после сопряжения, чтение измерений 0,28–0,30 мВ и
RUN → HOLD → RUN с ответами прибора. Системный `/dev/rfcomm*` не создавался.

Автоматические тесты дополнительно используют синтетические пакеты и имитацию
транспортов. Другие BLE-профили и температурные/специальные значения ещё не
проверены. Осциллограф и генератор не реализованы: используемый протокол
описывает мультиметр.

## Проверки

Node.js 18+ без установки пакетов:

```sh
cd web
npm test
```

Дополнительный браузерный тест: установить Python Playwright, запустить сервер и
выполнить `python3 web/tests/browser_check.py`. По умолчанию используется установленный
`/usr/bin/google-chrome`; другой путь можно передать через `DM40_CHROME`.

## Источники

- [DM40-Wireless](https://github.com/Urobotos/DM40-Wireless) — экран, команды, шкалы и BLE.
- [dm40ble](https://github.com/rockets-cn/dm40ble) — второй вариант BLE-характеристик.
  Предположительные режимы и XOR checksum из него не перенесены: они расходятся с
  анализом прошивки в этом репозитории и DM40-Wireless.
- [DM40Visor](https://github.com/mriscoc/DM40Visor) — подтверждение альтернативного BLE-профиля.
- [ATK-XTOOL protocol analysis](https://gist.github.com/holly-hacker/dfa54111cbdbe72f97bf5fcd02441307)
  — дополнительный профиль FFFF/FF01/FF02; источник явно маркирован как LLM analysis.
